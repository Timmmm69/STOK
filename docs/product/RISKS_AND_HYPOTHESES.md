# Риски и гипотезы

Статус: рабочий реестр. Риск — возможный ущерб; гипотеза — проверяемое предположение; будущая идея не является обязательством.

## Риски

| ID              | Риск                                                            | Проверка / снижение                                                 |
| --------------- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| `R-PRODUCT-001` | Маркировка удвоит труд и будет обходиться сотрудниками          | Замер старого/нового процесса на 100 вещах; stop criterion          |
| `R-OPS-001`     | Ценники перемешиваются или печать даёт неверные диапазоны       | Реальный принтер, сверка, история заданий и допечатки               |
| `R-PAYMENT-001` | Ручной терминал расходится с системой                           | Pending-состояние и ежедневная сверка                               |
| `R-DATA-001`    | Старый остаток делает аналитику неполной                        | Явный охват переноса и уровень доверия                              |
| `R-FINANCE-001` | Расчётная себестоимость воспринимается как точная               | Явное название, версия метода, запрет точной категорийной прибыли   |
| `R-LEGAL-001`   | Фискальные/возвратные/персональные требования меняют flow       | Юридическая проверка до пилота                                      |
| `R-TECH-001`    | Печать или нестабильная сеть потребуют локальный bridge/offline | Прототип оборудования и наблюдение в поле до архитектурного решения |
| `R-SCOPE-001`   | Ранний SaaS/ИИ/аналитика отвлекут от основной связи вещи        | Quality gate по scope и вертикальная последовательность             |
| `R-COST-001`    | Эксплуатация превышает ориентир $30/месяц                       | Один процесс/БД, измерение инфраструктуры после пилота              |

## Гипотезы

| ID                | Гипотеза                                                         | Способ проверки                                  |
| ----------------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| `H-PILOT-001`     | Поштучный учёт ценнее добавленного труда                         | Полевой пилот и `METRIC-ECONOMICS-001`           |
| `H-COST-001`      | Средняя себестоимость партии достаточна для первого решения      | Интервью владельца и решения по реальным партиям |
| `H-MIGRATION-001` | Поэтапный перенос остатка лучше полного                          | Сравнить труд, охват и полезность аналитики      |
| `H-PAYMENT-001`   | Ручное подтверждение терминала приемлемо                         | Расхождения и время оплаты в пилоте              |
| `H-UX-001`        | Партия+категория+цена+количество достаточно для массовой приёмки | Ошибки и обходы сотрудника приёмки               |
| `H-EXPANSION-001` | Нейтральное ядро поддержит соседние форматы                      | Не проверять до успешного секонд-хенд MVP        |

## Будущие идеи, не требования

Фото и детальные атрибуты; онлайн-канал; прогнозы; встроенный ИИ; тарифные разрешения; multi-store; одинаковые SKU с количественным остатком; автоматическая интеграция терминала; полноценный offline. Каждая идея требует собственного evidence и execution plan.
