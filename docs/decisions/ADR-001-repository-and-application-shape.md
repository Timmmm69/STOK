# ADR-001: форма репозитория и приложения

Статус: accepted, 2026-07-18.

## Контекст

Один собственный магазин, небольшой поток и бюджет эксплуатации около $30/месяц требуют минимальной поставки. Разработка идёт последовательными срезами через Codex.

## Решение

Один Git-репозиторий, один `package.json`, одно Next.js full-stack приложение и одна PostgreSQL. UI, HTTP и application services поставляются вместе.

## Альтернативы

Монорепозиторий frontend/backend отклонён: добавляет release/tooling без текущей независимости. Микросервисы отклонены: сеть, распределённые транзакции и эксплуатация не решают пилотную проблему. BaaS-only отклонён: критические транзакции/история требуют явного серверного слоя и переносимости.

## Последствия и риски

Простые локальная разработка и deployment; границы защищаются логически, а не процессами. Риск «big ball of mud» снижают модульные контракты и проверки.

## Условия пересмотра

Измеренная независимая нагрузка, изоляция отказа/команды, аппаратная локальность или невозможность безопасно поставлять один процесс.
