# ADR-008: вход через Google только для приглашённых пользователей

Статус: accepted, 2026-07-18.

## Контекст

Первая рабочая версия будет сайтом в интернете. Владелец выбрал вход через Google, свободная регистрация закрыта, а домен ещё не выбран. Нельзя публиковать данные магазина до появления проверенной сессии и серверного контекста организации.

## Решение

- Использовать стабильную Better Auth 1.6.23 с Google OAuth и PostgreSQL/Prisma adapter.
- Заранее создавать приглашённого владельца через seed, используя адрес из окружения, а не из исходного кода.
- Отключить автоматическое создание новых пользователей через Google.
- Разрешать бизнес-запрос только если действующая сессия принадлежит приглашённому адресу и пользователь связан с организацией на сервере.
- Хранить сессии и связи Google в PostgreSQL; срок сессии первого среза — 12 часов с обновлением не чаще часа.
- Не добавлять рабочему приложению тестовый или аварийный обход входа. Автоматические браузерные тесты создают сессию только через тестовую возможность Better Auth вне `src`.
- До выбора домена использовать только локальный адрес возврата; production-адрес и ключи создаются отдельно.

## Отклонённые альтернативы

- Собственные пароли: требуют безопасного восстановления, проверки почты и дополнительной защиты без пользы для одного владельца.
- Auth.js v5: на дату решения официальная установка всё ещё использует предварительный канал `beta`, что нарушает правило стабильных зависимостей.
- «Секретная ссылка» без входа: не является контролем доступа.
- Свободная регистрация: преждевременно создаёт чужие организации до готовности подписного сервиса.

## Последствия

Для реального входа владелец вручную создаёт Google OAuth credentials и позже добавляет production-домен. Отказ Google временно мешает новому входу, но не должен раскрывать данные. Перед расширением на других клиентов потребуются приглашения, дополнительные роли, восстановление доступа и решение о втором способе входа.
