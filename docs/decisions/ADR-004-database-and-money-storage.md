# ADR-004: база данных и деньги

Статус: accepted, 2026-07-18.

## Контекст

Складские/денежные операции должны быть атомарны и проверяемы; точность денег критична. Будущая SaaS-изоляция не должна доверять клиенту.

## Решение

PostgreSQL — источник персистентных фактов; Prisma schema и неизменяемая последовательность SQL-миграций задают структуру. Деньги — целое число минимальных единиц плюс валюта. Tenant-owned данные имеют server-validated `organization_id` и tenant-scoped ограничения.

## Альтернативы

`float` отклонён из-за ошибок представления. Decimal допустим для коэффициентов, но не заменяет целые суммы. Document DB отклонена: ограничения/транзакции/сверка естественны реляционно. Database-per-tenant отложена как дорогая для первого SaaS-этапа.

## Последствия и риски

Конкретная ширина целого, валюта и округление утверждаются до денежных таблиц. ORM не заменяет constraints и concurrency tests. Технический `HarnessState` не становится бизнес-таблицей.

## Условия пересмотра

Юридическое требование, подтверждённая multi-currency модель или пределы, не покрываемые выбранным представлением.
