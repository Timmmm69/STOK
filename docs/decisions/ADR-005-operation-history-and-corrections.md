# ADR-005: история операций и корректировки

Статус: accepted, 2026-07-18.

## Контекст

Удаление продажи/платежа/движения разрушает сверку. При этом полное event sourcing преждевременно.

## Решение

Критические факты append-only по смыслу; исправление — связанная отменяющая, возвратная, списывающая или восстанавливающая операция. Текущий статус/остаток может храниться как транзакционно согласованная проекция. Метод расчёта и значимый шаблон версионируются.

## Альтернативы

Mutable CRUD отклонён из-за потери доказательств. Полное event sourcing отклонено из-за стоимости replay/versioning и отсутствия необходимости для всех данных. Database audit trigger как единственный механизм отклонён: он не выражает бизнес-причину.

## Последствия и риски

Схема сложнее простого статуса; каждое действие требует причины, связи и теста атомарности. Retention/редакция персональных данных требуют отдельной юридической политики.

## Условия пересмотра

Доказанная необходимость полного replay/temporal query либо юридическое требование удаления конкретного класса данных.
