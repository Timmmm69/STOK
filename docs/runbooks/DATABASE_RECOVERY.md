# Восстановление базы

Статус: локальная процедура и требования; production backup ещё не настроен.

## Локальная проверка

1. Зафиксируйте имя контейнера через `docker compose ps`.
2. Создайте custom-format dump `pg_dump` внутри контейнера и скопируйте файл через `docker compose cp` в отдельный каталог backup.
3. Поднимите отдельную пустую PostgreSQL того же major-релиза.
4. Выполните `pg_restore --clean --if-exists` только в проверенную recovery DB.
5. Примените миграции, запустите integration/health и запишите фактическое время/ошибки.

Никогда не проверяйте restore поверх единственной рабочей базы. Имя/URL цели сверяются до destructive шага.

## До production

Нужны владелец, расписание, шифрование, off-site хранение, retention, RPO/RTO, мониторинг неудачных backup, ротация ключей и регулярный restore drill. Наличие файла backup без успешного восстановления не считается защитой.
