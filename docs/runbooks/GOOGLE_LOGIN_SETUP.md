# Настройка входа через Google

Статус: обязательная ручная настройка перед первым реальным входом и размещением в интернете.

## Почему ключей нет в репозитории

Google выдаёт идентификатор и секрет конкретному владельцу приложения. Секрет нельзя публиковать в Git, сообщении об ошибке или клиентском коде. Репозиторий содержит только названия переменных и безопасные тестовые значения для автоматических проверок.

## Локальная настройка

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) под аккаунтом первого владельца.
2. Создайте отдельный проект для STOK.
3. Настройте экран согласия OAuth. Пока приложение тестовое, добавьте владельца в список разрешённых тестовых пользователей.
4. Создайте OAuth Client ID типа **Web application**.
5. Добавьте разрешённый адрес возврата:

   `http://localhost:3000/api/auth/callback/google`

6. При необходимости добавьте разрешённый источник:

   `http://localhost:3000`

7. Скопируйте Client ID и Client Secret в локальный `.env`:

   ```text
   BETTER_AUTH_URL=http://localhost:3000
   BETTER_AUTH_SECRET=<случайная строка не короче 32 символов>
   GOOGLE_CLIENT_ID=<Google Client ID>
   GOOGLE_CLIENT_SECRET=<Google Client Secret>
   AUTH_ALLOWED_EMAIL=<адрес приглашённого владельца>
   ```

8. Выполните `pnpm db:seed`, затем `pnpm dev` и откройте `http://localhost:3000/login`.

Seed заранее создаёт только приглашённого владельца. Better Auth запрещает Google создавать постороннего пользователя, а сервер повторно сверяет разрешённый адрес.

## После выбора домена

Создайте или обновите отдельные production credentials:

- `BETTER_AUTH_URL=https://ваш-домен`;
- разрешённый источник `https://ваш-домен`;
- адрес возврата `https://ваш-домен/api/auth/callback/google`.

Google требует точного совпадения адреса возврата. Production использует HTTPS, отдельный случайный секрет сессии и управляемое хранилище переменных окружения. Локальные ключи не копируются в production.

## Ручная проверка

- Разрешённый Google-аккаунт входит и попадает на `/setup`.
- Другой Google-аккаунт не создаёт пользователя и не получает доступ.
- После выхода `/setup` снова требует вход.
- После перезапуска сервера действующая сессия ведёт себя согласно установленному сроку.
- В ответах, логах и сборке нет Client Secret и секрета сессии.

Официальные инструкции: [Google OAuth для серверного веб-приложения](https://developers.google.com/identity/protocols/oauth2/web-server) и [Google provider Better Auth](https://better-auth.com/docs/authentication/google).
