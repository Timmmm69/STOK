## Цель

Превратить репозиторий в единый источник продуктовой и технической истины: сохранить исходную концепцию, создать согласованный Product Compass и нормативные правила, зафиксировать архитектуру и ADR, а затем построить воспроизводимый минимальный Next.js/PostgreSQL harness с `/health`, тестами и CI — без функций магазина.

## Область задачи

- Историческая копия полной концепции и нормативная продуктовая документация.
- Аудит противоречий, рисков, гипотез и открытых вопросов.
- Архитектура одного TypeScript/Next.js модульного монолита с PostgreSQL, Prisma и Zod.
- ADR для формы репозитория, стека, модульности, данных, истории операций и quality gates.
- Короткая карта `AGENTS.md`, runbook'и и Definition of Done.
- Минимальное техническое приложение: страница и endpoint `/health`, безопасный timeout, структурированные логи, техническая миграция и детерминированный seed.
- Unit, HTTP, PostgreSQL integration и Playwright smoke tests.
- Автоматические проверки форматирования, типов, границ, циклов, документов, секретов и миграций.
- GitHub Actions для pull request.
- Управляемая последовательность вертикальных срезов и проект следующего execution plan.

- CI не требует production-секретов и использует PostgreSQL.
- Продуктовые функции отсутствуют; следующий вертикальный срез только спроектирован.
- Diff проверен, план завершён и создан требуемый Git-коммит.

## Риски

- Docker Desktop может не запуститься или локальный порт БД может быть занят.
- Актуальные major-версии TypeScript, ESLint, Prisma и Next.js могут иметь несовместимость, выявляемую только установкой/build.
- Prisma 7 требует ESM, явный output generated client и PostgreSQL driver adapter.
- OneDrive и Windows могут проявить различия file watching/locking относительно Linux CI.
- Пилот зависит от реального принтера, сканера, терминала и дисциплины сотрудников; harness этого не доказывает.
- Документация может создать ложное ощущение утверждённости открытых юридических и операционных решений; статусы должны быть явными.

## Принятые допущения

- Рабочее название — STOK; оно обратимо и не является решением о бренде.
- Валюта пилота ожидается BYN из концепции, но окончательное правило валюты/округления требует подтверждения до денежных функций.
- Первый интерфейс русскоязычный; локализация не реализуется в harness.
- Один репозиторий, один пакет и одно Next.js-приложение достаточны до появления измеренной причины усложнить поставку.
- Техническая таблица состояния harness допустима только для доказательства migration/seed и не является продуктовой моделью.
- Пилотные пороги из исходной концепции являются предварительными целями, а не рыночными фактами.

## Открытые вопросы

- Блокирующих создание harness вопросов не обнаружено.
- До пилота требуется утвердить модель ролей, валюту/округление, правила скидок, жизненные циклы исключений, оборудование, режим сети, политику возвратов и юридические требования Беларуси.
- Решение о переносе 300 кг текущего остатка принимается после полевого измерения.
- Production hosting, backup provider и печатный bridge выбираются после проверки пилота и бюджета.
