# Модель данных

Статус: правила хранения технической основы и первого продуктового среза.

## Источник истины

Схема Prisma и последовательность файлов миграций являются техническим источником истины для структуры PostgreSQL. Документ объясняет правила, но не заменяет миграции.

Техническая основа содержит `HarnessState`, а первый продуктовый срез добавляет пользователя, сессию, организацию, членство, магазин и запись безопасной начальной настройки. Таблиц партий, поставщиков, товаров, цен, штрихкодов, продаж, платежей, смен, возвратов, расходов, инвентаризации или аналитики ещё нет. `HarnessState` остаётся только техническим маркером и не расширяется продуктовыми полями.

## Окружения базы

- Локальная база разработки и тестовая база разделены именем базы и строкой подключения.
- Интеграционные и e2e-тесты не должны зависеть от пользовательских данных разработки.
- Seed детерминирован: повторный запуск приводит к одному известному состоянию, а не размножает записи.
- Секретные строки подключения не хранятся в Git; репозиторий содержит только безопасный пример конфигурации.

Фактические имена переменных и сервисов должны совпадать с `.env.example`, `docker-compose.yml` и scripts в `package.json`.

## Миграции

- Любое изменение схемы оформляется новой именованной миграцией.
- Уже применённая или опубликованная миграция не редактируется задним числом.
- Миграция проходит проверку на чистой базе и на базе с предыдущей версией схемы.
- Разрушающее изменение требует плана совместимости, резервной копии и восстановления; в bootstrap такие изменения не нужны.
- Команды применения и локального сброса описаны в [LOCAL_SETUP.md](../runbooks/LOCAL_SETUP.md).

## Будущие инварианты схемы

- Бизнес-запись, принадлежащая клиенту, имеет обязательный `organization_id` и подходящие ограничения/индексы.
- Магазин принадлежит ровно одной организации; организация может иметь несколько магазинов, даже если первый интерфейс работает только с одним.
- Запись конкретной торговой точки имеет обязательный `store_id`; общие настройки организации не дублируются в магазине без доказанного переопределения.
- Уникальность бизнес-ключа, если она ограничена организацией, включает `organization_id`.
- Доступ фильтруется серверным контекстом организации; переданный клиентом идентификатор не даёт права доступа.
- Деньги сохраняются целым числом минимальных денежных единиц. Конкретная ширина целого типа выбирается по подтверждённым пределам и тестируется на переполнение.
- Временные поля хранятся с однозначной временной зоной; локальная зона используется только для отображения и утверждённых бизнес-границ дня.
- Финансовые и складские факты исправляются связанными компенсирующими записями, а не физическим удалением.
- Критические записи имеют достаточно данных для идемпотентности, аудита и расследования.
- Межмодульная связь не даёт модулю права читать или изменять внутренние таблицы владельца напрямую.

## Транзакции и конкурентность

Application service задаёт транзакционную границу критического сценария. Репозитории участвуют в переданном контексте транзакции, а не открывают независимые транзакции внутри одного атомарного действия. Для каждого сценария до реализации определяются конкурентные конфликты, уникальные ограничения и поведение повтора.
