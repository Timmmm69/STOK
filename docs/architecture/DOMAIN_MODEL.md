# Доменная модель

Статус: нормативная карта областей ответственности. Доменные сущности harness не реализует.

## Подход

Система развивается как модульный монолит. Границы определяются ответственностью и инвариантами, а не страницами интерфейса или таблицами. Модуль владеет своей моделью и предоставляет другим модулям только явный публичный контракт.

## Будущие доменные области

| Модуль          | Предполагаемая ответственность для уточнения               | Статус bootstrap |
| --------------- | ---------------------------------------------------------- | ---------------- |
| `organizations` | Контекст организации и её настройки                        | Только граница   |
| `identity`      | Идентичность, роли и серверная авторизация                 | Только граница   |
| `suppliers`     | Справочник контрагентов-поставщиков                        | Только граница   |
| `procurement`   | Факты закупки и их жизненный цикл                          | Только граница   |
| `catalog`       | Описание и классификация уникальных товаров                | Только граница   |
| `pricing`       | Назначение и история цен                                   | Только граница   |
| `labeling`      | Задания печати, диапазоны, перепечатка и сверка маркировки | Только граница   |
| `inventory`     | Остатки и складские движения                               | Только граница   |
| `sales`         | Факт продажи и его состояние                               | Только граница   |
| `payments`      | Денежные операции, связанные с расчётами                   | Только граница   |
| `shifts`        | Операционная смена и сверка                                | Только граница   |
| `expenses`      | Операционные расходы                                       | Только граница   |
| `analytics`     | Производные показатели и чтение для анализа                | Только граница   |
| `exceptions`    | Явная обработка расхождений и исключений                   | Только граница   |
| `audit`         | Неизменяемый след критических действий                     | Только граница   |

Названия и ответственность выведены из утверждённых потоков, но не подтверждают состав агрегатов, команд, событий или таблиц до соответствующего вертикального среза.

## Общие будущие инварианты

- Владение организацией выражается явно и проверяется на сервере.
- Модуль, создающий факт, владеет правилами его изменения.
- Финансовые и складские факты не исчезают при исправлении; используется компенсирующее действие.
- Критическое изменение атомарно и пригодно для аудита.
- Идемпотентность определяется на границе каждого повторяемого сценария.
- Денежная сумма — целое число минимальных единиц, не число с плавающей точкой.

## Интеграция модулей

Прямой импорт разрешён только через публичный контракт модуля. Совместное чтение таблиц, импорт внутреннего репозитория или использование внутреннего Prisma-типа другого модуля запрещены. Если одному сценарию нужны несколько областей, orchestration выполняется в явно назначенном application service с документированной транзакционной границей.
