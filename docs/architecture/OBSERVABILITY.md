# Наблюдаемость

Статус: baseline harness; продуктовые SLI определяются перед пилотом.

## Логи

Pino пишет JSON с `timestamp`, `level`, `event`, длительностью и безопасным контекстом. Строки подключения, токены, платёжные реквизиты, полные тела запросов и персональные данные запрещены. Неизвестная ошибка получает стабильный публичный ответ; техническая причина не отражается клиенту.

Health использует события `health.check.completed` и `health.database.unavailable`; ответ отдельно показывает приложение и БД. Correlation/idempotency identifiers допустимы, если не несут пользовательские данные.

## Метрики и трассировка

Harness не добавляет платный APM. До production выбираются минимальные SLI: доступность критического flow, latency, доля ошибок, pending-операции и насыщение БД. Distributed tracing не нужен одному процессу без доказанной диагностической ценности.

## Алерты и аудит

Технический alert не заменяет продуктовый центр исключений, а audit не заменяет лог. Перед пилотом фиксируются владелец инцидента, канал оповещения и runbook. Финансовые/складские факты аудируются доменными операциями, а не реконструируются из временных логов.
