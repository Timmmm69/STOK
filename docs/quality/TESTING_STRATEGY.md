# Стратегия тестирования

## Слои доказательств

1. Модульные тесты: чистые правила health, приглашённого адреса и безопасной настройки с подменяемыми зависимостями.
2. HTTP: точные `200`/`503`, `401`/`201`/`409`, JSON и отсутствие внутренних деталей.
3. PostgreSQL: реальные миграции, повторяемый seed, транзакционное создание организации/магазина и отсутствие дублей в изолированной тестовой БД.
4. Сборка: production-компиляция Next.js.
5. Браузер: Chromium проверяет `/health`, запрет анонимного `/setup`, настройку приглашённым тестовым владельцем и сохранение после перезагрузки.

Тест проверяет поведение, а не наличие файла. Подмена не заменяет PostgreSQL на критической границе. Фиксированные задержки не используются, когда можно ждать наблюдаемое состояние. Тестовая база сбрасывается независимо и никогда не использует производственные секреты. Настоящий обмен с Google требует отдельной ручной проверки с credentials владельца; браузерные тесты используют официальный тестовый модуль Better Auth только вне рабочего приложения.

Для будущего вертикального среза обязательны happy path, validation/authorization, duplicate/idempotency, concurrency/transaction rollback, correction/audit и user-visible recovery пропорционально риску.
